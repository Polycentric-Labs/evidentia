## Goal

Add generic, public FDA medical-device support: (1) the Section 524B premarket-cybersecurity security
control categories as a real catalog; (2) ISO 14971 + AAMI SW96 license-respecting stubs + a 524B↔14971↔SW96
crosswalk; (3) a demo-only FDA route on the public web console (not the landing); (4) an FDA FAQ/explainer.

## Verified regulatory facts (primary-source-confirmed before authoring)

These were confirmed against fda.gov / uscode.house.gov / iso.org / aami.org. Two spec inputs were
**corrected** after primary-source review:

- **Guidance (cite this edition):** FDA final guidance *"Cybersecurity in Medical Devices: Quality
  **Management** System Considerations and Content of Premarket Submissions"*, **Feb 3, 2026 edition**
  (supersedes the June 27, 2025 and Sept 27, 2023 editions; the earlier ones omit "Management").
- **The eight security control categories** come from the guidance's **Section V.B.1** (verbatim):
  Authentication; Authorization; Cryptography; Code, Data, and Execution Integrity; Confidentiality;
  Event Detection and Logging; Resiliency and Recovery; Updatability and Patchability.
  - **#8 nuance:** the guidance is internally inconsistent — **Appendix 1**'s subsection header for the same
    category reads *"Firmware and Software Updates."* We use the §V.B.1 name and note the Appendix-1 variant
    (decision below), rather than mislabel an Appendix-1 header.
- **Statute:** FD&C Act **Section 524B** (21 U.S.C. 360n-2), captioned *"Ensuring cybersecurity of devices"*
  (the phrase *"Ensuring Cybersecurity of Medical Devices"* is the FDORA §3305 amending-heading, not the
  §524B caption). Added by **§3305 of FDORA** (Pub. L. 117-328), effective **March 29, 2023**; requires
  cyber-device premarket submissions to include a vulnerability-management plan, secure-by-design processes
  covering updates/patches, and an SBOM.
- **Standards (license-respect — stub + cite, never reproduce):** **ISO 14971:2019** (*Medical devices —
  Application of risk management to medical devices*; risk = a *combination* of probability of harm and
  severity, commonly operationalized as probability × severity); **ANSI/AAMI SW96:2023** (*Standard for
  medical device security — Security risk management for device manufacturers*); **AAMI TIR57:2016 (R2023)**
  (*Principles for medical device security — Risk management*).
- **Copyright:** the FDA guidance + statute are U.S.-Government works (17 U.S.C. 105) — paraphrasable in our
  own words. ISO 14971 / AAMI SW96 / TIR57 are copyrighted — license-stub + cite only.

## Decisions

1. **8th category:** use the canonical §V.B.1 names; control #8's description notes the Appendix-1 variant
   ("Firmware and Software Updates"). Catalog id `fda-524b-appendix1`.
2. **Demo signed-artifact:** a **display fixture** (illustrative signature object on synthetic, banner-labeled
   data) — the static demo verifies nothing in-browser; **no signing key in the repo**.
3. **Demo route:** registered demo-only (`{IS_DEMO && <Route path="demo/fda" …/>}`); the landing/index is
   unchanged; kept inside the normal `AppLayout`.

## Components

1. **Catalog — DONE.** `catalogs/data/us-federal/fda-524b-appendix1.json` (Tier A, 8 controls), registered
   via `regenerate_manifest.py` (framework count 92 → 93); catalog + `gap analyze --frameworks
   fda-524b-appendix1` integration tests.
2. **Stubs + crosswalk.** `stubs/iso-14971.json` + `stubs/aami-sw96.json` (the `iec-62443.json`
   `placeholder/license_required/license_url` pattern, no standard text) + `mappings/` crosswalk tying
   524B Appendix-1 ↔ ISO 14971 ↔ SW96, encoding in metadata: *safety risk = probability × severity
   (ISO 14971) vs security risk = exploitability × severity (SW96/TIR57), on a shared patient-harm severity
   axis* (the differentiated content). The risk-axis framing is attributed as a paraphrase of SW96/TIR57,
   not quoted from the FDA guidance.
3. **Demo route.** Port `fda-fixtures.ts` + `FdaDemoPage.tsx` from the decoupled prototype, generic-synthetic
   org, banner-labeled, register at `demo/fda` only; commit a synthetic, display-fixture-signed
   `examples/fda-524b-DEMO-example-assessment.oscal.json`. FdaDemoPage Vitest + fixture-shape test.
4. **FAQ.** `docs/wiki/fda-medical-device-compliance.md` (+ `mkdocs.yml` nav; auto-syncs): what 524B +
   the control categories are, the safety-vs-security risk distinction, a link to `#/demo/fda`, FDA/ISO/AAMI
   source links, "illustrative; feedback welcome."
