# v0.10.11 plan — Public demo completion + traceability + hygiene

> (off `main` @ the v0.10.10 tag). Push/tag are release-authority-gated. The full
> `/pre-release-review` + 3× gate runs before the tag.

## Status (2026-06-17)

Planning. Three tracks, demo-first (the webapp demo is the priority), then traceability, then
hygiene. The aggressive full CLI↔GUI parity build-out is **out of scope** — it is its own
dedicated, subagent-driven session (**v0.10.12**, per [`ROADMAP.md`](ROADMAP.md)).

## Goal

Finish the public demo surface, ship the threat→control→evidence spine as a real signed
capability (not just a demo visual), and clear the v0.10.10 follow-on hygiene.

## Decisions (locked)

1. **Traceability deliverable = a Sigstore-signable OSCAL matrix** (reuses the existing OSCAL
   signing pipeline; on the "everything is verifiable evidence" brand; sets up the v0.11 TM-BOM).
2. **OSCAL view = show the run's emit + verify** — a read-mostly console page rendering a gap
   run's emitted OSCAL Assessment Results + a verify panel (reuses the FDA-demo signed-artifact
   pattern), not an interactive upload-and-verify surface (that is a v0.10.12 parity item).
3. **Full CLI↔GUI parity → v0.10.12** (dedicated session). v0.10.11 does only the two targeted
   GUI-fills below.
4. Generic / public-safe content only — no customer/third-party references anywhere.

## Components

### Track 1 — Webapp demo completion (priority)

1. **Deploy the main console demo** → `demo.evidentiagrc.com`. The static `VITE_DEMO` console
   bundle already exists (shipped v0.10.10); add a `packages/evidentia-ui/vercel.json`
   (`VITE_DEMO=true npm run build` + SPA rewrite, mirroring the FDA-demo config) and a deploy
   runbook. **Tier-4 deploy (operator-driven on Vercel/Cloudflare).**
2. **FDA-index build mode** — a `VITE_DEMO_FDA_INDEX` flag that renders `FdaDemoPage` full-bleed
   as the index (outside `AppLayout`), so `fdademo.evidentiagrc.com` can serve the **in-repo**
   bundle and the decoupled prototype is retired (single source of truth). Vitest for the flag.
3. **OSCAL emit/verify console view** (GUI-fill) — a new route that shows a gap run's emitted
   OSCAL Assessment Results + a verify panel (digests + GPG/Sigstore signature status), reusing
   the FDA-demo signed-artifact components. Read-mostly. Chips at the `check_parity` CLI-only
   backlog without attempting full parity.

### Track 2 — Control↔Threat Traceability Matrix (signed OSCAL)

Promote threat→control→evidence from a demo visual into a first-class **GUI + CLI** capability
that emits a **Sigstore-signable OSCAL** matrix. Builds on `models/threat.py`
(AttackTechnique/Vulnerability/etc.) + the existing OSCAL exporter/signing. A CLI verb (e.g.
`evidentia traceability …` emitting the matrix as OSCAL, sign-able via the existing
`--sign-with-gpg/--sign-with-sigstore` path) + a GUI route. Generalist OSS. **At build-time this
gets its own `polycentric-labcoat` fleet** to lock the exact OSCAL representation before coding
(per the ROADMAP medical-device line). v0.10.11 ships the signed-OSCAL matrix slice; the
Threat-Dragon ingest + CycloneDX TM-BOM + residual-risk scoring is the v0.11 build.
