# Evidentia v0.10.8 — release-automation hardening + CLI↔GUI parity + GUI build-out (start)

**Status: PLANNED.** Patch on v0.10.7. The theme is *institutionalizing the quality discipline*: the safeguards that protected the v0.10.7 ship were largely AI-driven (run by hand via `/pre-release-review`); v0.10.8 wires them into the **automatic** release mechanism so the same quality, 3× validation, and accuracy hold on every release with no human in the loop — plus the first enforcement of "every CLI feature reaches the GUI," and the start of closing that gap.

Origin: a post-v0.10.7 safeguards sweep (2026-05-31) with two investigations — release-automation inventory + CLI↔GUI parity. Two findings drive the cycle:

1. **The irreversible publish is the least-gated path.** The full gate suite (pytest/mypy/ruff/osv/drift) runs in CI on push-to-`main`, but **not on the tag**; the version/doc-staleness guards live **only** in the local pre-push hook (no CI, not in `release.yml`). With `enforce_admins=false`, a tag pushed without the local hook reaches PyPI with none of them run.
2. **The GUI covers ~30% of the CLI.** 24 CLI groups → 8 GUI routes. 7 whole API groups exist only as generated types with no screen; 6 CLI subsystems have no API at all. The OpenAPI drift-gate keeps *types* in lockstep but enforces no *feature* parity, and masks the gap.

---

## Phase A — Release-hardening automation

- **A1 (D1) — tag-time gate job in `release.yml`.** A `gate` job (pytest + `mypy --strict` + ruff + `check_version_consistency.py` + `check_docs_health.py --strict` + `run_osv_scan.py`) that `publish-pypi` / `publish-container` `needs:` — so the **irreversible publish cannot fire on a red or stale tree**. ~3–4 min added to the release run; deliberate duplication of push-CI (different trigger).
- **A2 (D2) — CI mirror of the local-only staleness guards.** A `consistency` job on push/PR `main` running `check_version_consistency.py` + `check_docs_health.py --strict` (+ `gen_readme_releases.py --check`, uv.lock pin-drift, osps-crosswalk-drift), so these no longer depend on a configured local hook.
- **A3 (D3) — auto-regenerate the README on CHANGELOG change.** Wire `gen_readme_releases.py` **write-mode** into the pre-push hook (regenerate; fail if the README changed → "commit the regen"), closing the exact staleness that the v0.10.7 README hit (the `--check` is version-only by design).
- **A4 (D6) — real CI secret-scan.** A gitleaks (or equivalent) CI job, complementing the local `check_secrets.sh`. (`bump_version.py --verify` (D5) intentionally SKIPPED — A1 covers the risk and `bump_version.py` stays a pure substituter.)

## Phase B — Commit-signature enforcement (Tier-4 GitHub mutation)

- **B1 (D4) — required-signatures ruleset on `main` with `enforce_admins=true`.** Server-side block of any unsigned commit (even a direct admin push), making the F-V107-1 admin-bypass impossible to repeat. The v0.10.7 local pre-push check (`check_commit_signatures.py`) stays as defense-in-depth. **Applying the ruleset is a Tier-4 `gh api` mutation — surfaced for explicit approval** when implemented. Pre-req: Allen's signing setup configured on every machine he pushes from.

## Phase C — CLI↔GUI parity mechanism (the lockstep)

- **C1 (D7) — `docs/cli-gui-parity.yaml` manifest** — one row per CLI leaf command (`cli` / `api` / `gui` / `status` ∈ full | api-only | cli-only | exempt), seeded from current state (~7 full, ~7 api-only, ~6 cli-only, exempt for `mcp serve` etc.).
- **C2 (D7) — `scripts/check_parity.py` CI gate** (sibling to `openapi-drift`): completeness (walk the live Typer tree; fail on any unlisted CLI leaf), API-existence (each claimed op in `openapi.json`), **GUI-existence** (each claimed route in `App.tsx` AND wired in `lib/api.ts`/a hook — catches the types-only illusion), and a **debt-ratchet** (fail if `cli-only` count increases). Advisory for one release, then blocking. Hosted by extending the `api-gui-parity-tracker` skill.
- **C3** — `docs/parity-coverage.md` auto-generated burndown + a README badge.

## Phase D — GUI build-out (start; phased across releases)

- **D8 — close the parity gap, Tier-B first** (API already exists → just add the screen): collect/collectors, tprm, poam, conmon, model-risk, integrations, ai-gov, explain. Each release ratchets the `cli-only` / `api-only` debt down. v0.10.8 lands the **first** 1–2 Tier-B screens as the pattern; the rest follow across v0.10.x/v0.11.

## Phase G — Automatic-upkeep mechanism (candidates — pick before adopting)

Surfaced during the post-v0.10.7 hygiene pass (the 7 stale branches were deleted and **`deleteBranchOnMerge` was enabled**, 2026-05-31, so PR head branches now auto-delete on merge). Candidates to fold into the project's *automatic* upkeep so hygiene doesn't depend on anyone remembering:

- **Session → memory/roadmap capture.** Today only *release* work auto-captures (the `/pre-release-review` skill commits process+results to memory each step); ad-hoc work does not. Options: strengthen the end-of-session capture directive in `CLAUDE.md`; a `Stop` hook that nudges when `packages/`/`docs/` changed; a periodic `consolidate-memory` routine (which also prunes the over-size MEMORY.md index).
- **Stale-branch flagging** — a scheduled workflow listing branches merged-or-stale > 30 days (covers non-PR branches, which `deleteBranchOnMerge` does not).
- **Dependabot auto-merge** — auto-merge green patch/minor Dependabot PRs (4 are open + manual today).
- **Doc / pointer-rot cadence** — `check-pointer-rot` + `doc-runtime-verifier` on a schedule (stale memory pointers + doc drift).
- **Research-resync** — re-run the positioning / competitive / integration-survey research streams on a cadence (those synthesis docs decay).
- **Quarterly safeguards re-sweep** — re-run the automated-vs-manual audit periodically to catch new gaps. *(Already scheduled + healthy: Scorecard, CodeQL, OSPS-conformance, mutmut.)*
