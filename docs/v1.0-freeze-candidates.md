# v1.0 freeze candidates — the surface delta

> **Status**: DRAFT (v0.12 freeze-prep). This document is a **proposal
> register**, not a contract. Nothing here is frozen until it lands in
> [api-stability.md](api-stability.md), which remains the single
> NORMATIVE source of what Evidentia promises.
>
> **Purpose**: `api-stability.md` was promoted to NORMATIVE at v0.9.7.
> Sixteen releases have shipped since. This document enumerates the
> surfaces that exist today but are **not** covered by that contract, so
> the v1.0 stability promise is a deliberate decision per surface rather
> than an accident of what happened to get written down in 2026-05.
>
> **Canonical location**: `docs/v1.0-freeze-candidates.md`.
> **Cross-references**: [api-stability.md](api-stability.md),
> [deprecation-calendar.md](deprecation-calendar.md),
> [v1.0-transition.md](v1.0-transition.md).

## How to read this document

Each candidate carries a **proposed disposition**:

| Disposition | Meaning at v1.0 |
|---|---|
| **FREEZE** | Add to `api-stability.md`; semver guarantees apply |
| **FREEZE (provisional)** | Public and documented, but explicitly re-decidable at the v1.0 candidate review |
| **LEAVE UNFROZEN** | Deliberately outside the contract; free to change in a minor |
| **DECIDE** | Genuinely open; needs a call before v1.0 |

The **gate** enforcing the frozen half is `scripts/check_public_surface.py`
(pre-push + the `consistency` CI scope). It executes every §5 import,
diffs the frozen MCP tool table against the live server, and asserts
every frozen env var still appears in `packages/*/src`.

## 1. Environment variables — the largest gap

**8 frozen, 51 live, 43 unfrozen.** This is the single biggest delta
between the contract and the shipped product. `api-stability.md`'s
env-var section froze the set that existed at v0.9.7 and was never
revisited.

Not everything should be frozen. The proposal groups the 43 by what
kind of promise each deserves.

### 1a. Store / cache directory overrides — proposed **FREEZE**

Operators wire these into container mounts, air-gap deployments, and
multi-tenant layouts. They are exactly the class of var whose rename
breaks a production deployment silently, and the 8 already-frozen vars
are the same shape (`EVIDENTIA_POAM_STORE_DIR`,
`EVIDENTIA_EVIDENCE_STORE_DIR`, …) — freezing these makes the contract
internally consistent rather than an accident of timing.

| Env var | Purpose |
|---|---|
| `EVIDENTIA_GAP_STORE_DIR` | Gap-report store directory |
| `EVIDENTIA_VENDOR_STORE_DIR` | TPRM vendor store directory |
| `EVIDENTIA_MODEL_STORE_DIR` | Model-risk store directory |
| `EVIDENTIA_METRIC_STORE_DIR` | Governance-metric store directory |
| `EVIDENTIA_RETENTION_STORE_DIR` | Retention-metadata store directory |
| `EVIDENTIA_WORKFLOW_STORE_DIR` | Workflow store directory |
| `EVIDENTIA_CHALLENGE_STORE_DIR` | Challenge store directory |
| `EVIDENTIA_AI_ACQUISITION_DIR` | M-25-22 acquisition store directory (v0.11.0) |
| `EVIDENTIA_CATALOG_DIR` | User catalog-override directory |
| `EVIDENTIA_EXPLAIN_CACHE_DIR` | Control-explanation cache directory |

### 1b. API server flags — proposed **FREEZE**

Deployment-shaping, and two of them are security-relevant (turning
`EVIDENTIA_API_SECURITY_HEADERS` off, or `EVIDENTIA_API_DEV` on, changes
the app's security posture). A silent rename would fail *open*.

`EVIDENTIA_API_OFFLINE` · `EVIDENTIA_API_DEV` ·
`EVIDENTIA_API_SECURITY_HEADERS` · `EVIDENTIA_API_AUTH_TOKEN_FILE`

### 1c. CONMON file overrides — proposed **FREEZE**

`EVIDENTIA_CONMON_STATE_FILE` · `EVIDENTIA_CONMON_ALERT_DEDUP_FILE` ·
`EVIDENTIA_CONMON_DAEMON_STATUS_FILE` ·
`EVIDENTIA_CONMON_DAEMON_HISTORY_FILE`

The CONMON daemon is the surface operators automate against most
directly; its state paths belong in the contract.

### 1d. LLM + MCP configuration — proposed **FREEZE**

`EVIDENTIA_LLM_MODEL` · `EVIDENTIA_LLM_API_BASE` ·
`EVIDENTIA_LLM_TEMPERATURE` · `EVIDENTIA_MCP_SIGN_OUTPUTS` ·
`EVIDENTIA_MCP_SIGNER_FACTORY`

`EVIDENTIA_LLM_API_BASE` in particular is how air-gap operators point
Evidentia at a self-hosted endpoint — a load-bearing deployment knob.

### 1e. Credential variable NAMES — proposed **FREEZE (names only)**

`EVIDENTIA_POSTGRES_PASSWORD` · `EVIDENTIA_MYSQL_PASSWORD` ·
`EVIDENTIA_MSSQL_PASSWORD` · `EVIDENTIA_ORACLE_PASSWORD` ·
`EVIDENTIA_SMTP_PASSWORD` · `EVIDENTIA_WEBHOOK_SECRET` ·
`EVIDENTIA_SERVICENOW_USER` · `EVIDENTIA_SERVICENOW_PASSWORD` ·
`EVIDENTIA_SERVICENOW_INSTANCE_URL` · `EVIDENTIA_SERVICENOW_TABLE` ·
`EVIDENTIA_SIGNING_KEY_PASSPHRASE` ·
`EVIDENTIA_SIGNING_KEY_PASSPHRASE_FILE`

Freezing the **name** is what matters: these are wired into secret
managers, CI vaults, and Kubernetes `Secret` keys, where a rename means
a silent auth failure at the worst moment. Nothing about the *values* or
the resolution order is frozen.

### 1f. Deliberately **LEAVE UNFROZEN**

| Env var | Why not frozen |
|---|---|
| `EVIDENTIA_TEST_MODE` | Test-harness affordance, not an operator surface |
| `EVIDENTIA_SKIP_FRONTEND_BUILD` | Build-time only; not present at runtime |
| `EVIDENTIA_EDITOR_ALLOW_ANY` | Interactive-editor escape hatch |
| `EVIDENTIA_AUDIT_RO` | Internal read-only audit toggle |
| `EVIDENTIA_OSCAL_NS` | Overrides an OSCAL namespace we may need to move |
| `EVIDENTIA_SQLITE_SAFE_ROOT` | SQLite-collector path guard; internal safety mechanism |

### 1g. **DECIDE**

| Env var | The question |
|---|---|
| `EVIDENTIA_RBAC_TENANT` | Multi-tenancy is still evolving; freezing the var may pin a model we want to change |
| `EVIDENTIA_AI_OPERATOR` | Attribution default for AI-gov writes — freeze, or fold into a config file? |

## 3. The `Finding` / `SecurityFinding` inversion

**This is the most important item in this document**, because the
currently-published plan for it would break the wire format.

**Documented state.** `deprecation-calendar.md` and `api-stability.md`
§1 both describe `Finding` as the canonical name and `SecurityFinding`
as a "backward-compatible alias", with the alias scheduled for **removal
at v1.0.0**.

**Actual state.** It is the other way round:

```python
>>> from evidentia_core.models.finding import Finding, SecurityFinding
>>> Finding is SecurityFinding
True
>>> Finding.__name__
'SecurityFinding'
>>> Finding.model_json_schema()["title"]
'SecurityFinding'
```

`SecurityFinding` is the real class; `Finding` is the alias pointing at
it. So "remove the `SecurityFinding` alias" is not an alias removal at
all — it is a **class rename**, and the class name is the Pydantic
schema title, which appears in `openapi.json` and therefore in every
generated client.

**Proposed v1.0 plan** (three steps, none of them wire-breaking):

1. Migrate internal call sites from `SecurityFinding` to `Finding`
   (mechanical; ~50 sites).
2. Rename the class to `Finding` **with**
   `model_config = ConfigDict(title="SecurityFinding")`, so the OpenAPI
   schema component keeps its current name and no generated client
   breaks. The openapi drift gate will confirm a zero diff.
3. Keep `SecurityFinding` importable via a module-level `__getattr__`
   that emits a lazy `DeprecationWarning` — the alias direction finally
   matching the documentation, with a warning the calendar always
   promised but never emitted.

Then correct the calendar and `api-stability.md` §1 to describe what
actually happens. **DECIDE**: whether step 3's alias is removed at v1.0
or carried into v1.x. Carrying it is nearly free and spares integrators
a second migration.

## 4. The gap-report repository seam (v0.12.0)

`evidentia_core.gap_store.GapReportRepository` is new in v0.12.0: a
frozen-slots dataclass binding an explicit `root`, resolved once through
`get_gap_store_dir(root)`, with `save` / `load_latest` / `list` /
`load_by_key` delegating to the existing module functions. It exists so
callers can hold a store handle bound to a known root instead of relying
on ambient process state, and it ships with `GapStoreRootChangedError`
and an optional `root_revalidator` hook.

`evidentia_api.routers.gaps.create_stored_report_read_router(repository)`
builds a narrow read-only router over one repository. **It is not
mounted by `create_app()`** — it is an embedding seam, not a live route.

Proposed: **FREEZE (provisional)** — documented as public so integrators
can use it, with the freeze decision explicitly revisited at the v1.0
candidate review. The weakest part is `root_revalidator`, which has no
in-tree caller; if nothing uses it by v1.0, drop it rather than freeze it.

## 5. Surfaces confirmed already in step (no action)

Verified mechanically by `scripts/check_public_surface.py`:

- **MCP tools: 13 frozen, 13 live, exact match.** The append-only tool
  contract has held since v0.10.4.
- **REST URI prefixes**: every router mounts under `/api/<resource>` as
  §6 describes.
- **§5 library entry points**: all resolve — *after* the v0.12.0
  correction of four entries that had never resolved on any shipped
  release (see the `api-stability.md` revision history). That correction
  is the reason this gate now exists.
