# v0.13.1 plan: review deferrals with their reasons

**Status: DRAFT 2026-10-18**, opened at the v0.13.0 pre-tag review. Every item
below was found by that review and left out of v0.13.0 on purpose: each one
needs a design decision, a contract change or a source review that the release
window could not carry honestly. The review record is
`docs/releases/reviews/security-review-v0.13.0.md`; finding ids refer to the
per-subsystem reports kept with that review.

Scope philosophy: **close what the review opened, in the order of operator
exposure.** Nothing here adds a product surface.

---

## Authorization

- **CLI role gating.** Every mutating REST operation carries a role gate since
  v0.13.0 (decision D8), but about 45 CLI mutators still rely on the operator
  shell: `ai-gov`, `governance`, `model-risk`, `poam`, `tprm`, `risk`, `eval`,
  `explain`, `integrations`, `oscal` and `traceability`. The CLI identity is
  operator-asserted, so this is a least-privilege-automation gap rather than a
  privilege escalation. Decide the verb matrix, mirror the REST roles, and add
  the Typer walk to the test that already fails on an ungated REST mutator
  (`tests/integration/test_api/test_rbac_coverage.py`). Evidence: api-cli-mcp-ai F-5,
  probe F-V0130-PROBE-1.
- **Governance actor provenance.** Workflow and challenge payloads carry
  `actor`, `initiator`, step `status` and `history` from the client; the audit
  event records no principal. When an AuthProvider is configured, derive the
  actor from the authenticated principal, force new workflow steps to PENDING
  with server-side timestamps, and pass `user=` to the audit event. Evidence:
  api-sweep #6, api-cli-mcp-ai F-9.
- **Egress host allowlist for caller-supplied base URLs.** The Vanta, Drata,
  BitSight, SecurityScorecard, Google Workspace and Tableau routes still accept a
  host from the body; v0.13.0 confined the credential name to the integration
  and gated the routes. An operator-side allowlist would close the remaining
  "own credential to a caller-chosen host" path for writers. Evidence:
  imports-catalogs-exports F-5, api-cli-mcp-ai F-2.
- **Multi-tenant store root on the conmon reads.** `get_evidence_store_dir()`
  is called without a tenant on the conmon routes, as it is on the collector
  routes that write the store. Evidence: api-sweep note on item (c).

## Console

- **Console bearer token.** The console never sends `Authorization`; its
  credentialed flows enable only when `auth_configured` is true, so a deployment
  that follows the documented advice (set the token file) makes every console
  call a 401 unless a reverse proxy injects the header. v0.13.0 documents the
  proxy pattern; the durable fix is a token field held in memory with the CSP
  implications worked through. Evidence: ui-frontend F-1.
- **Health poll resets native catalog flows.** Both native catalog flows key
  their auth generation on `health.dataUpdatedAt`, and the layout polls health
  every 15 seconds, so in-flight loads abort and verified downloads disable.
  Evidence: ui-frontend F-2.
- **Remove copy says "permanently deletes".** v0.13.0 keeps the payload files
  on remove; the copy at `CatalogPage.tsx` still promises deletion. Evidence:
  ui-frontend F-3 (CWE-451).
- **Entra result download re-serialises.** The Entra/M365 download writes the
  parsed object instead of the validated wire text. Evidence: ui-frontend F-4.

## Collectors and registries

- **Registry snapshot refresh.** The packaged FedRAMP (as of 2026-09-10) and
  FCC (2026-09-09) snapshots are past the seven-day freshness limit, so a found
  and complete snapshot lookup exits 1 with `freshness: stale`, and a CMVP
  lookup can never exit 0 (`source_time_unsupported`). A refresh is a reviewed
  source capture plus an owner-approved replacement exception
  (`docs/designs/registry-collector-design.md`), so it waits for the owner.
  Evidence: probe-collectors D7.
- **SAM exclusions with several records read as ambiguous.** A UEI lookup whose
  firm has more than one exclusion reports `lookup_outcome: ambiguous` although
  every observation is an exact identifier match. Evidence: clocks-registries F-3.
- **Interpreter refusal surfaces as `dns_failure`.** The incident-clock DNS
  worker reports a `_base_interpreter()` refusal with the same code as a real
  resolver failure; a distinct code needs the closed code set reopened.
  Evidence: clocks-registries F-2.
- **DNS before the credential check.** Storage retention, enterprise retention,
  Entra/M365 and registry SAM resolve the host before refusing a missing
  credential; incident clock and Google Workspace check credentials first.
  Evidence: probe-collectors D6.
- **Partial Google Reports pull.** A Reports API page failure after the first
  page is invisible in the result. Evidence: collectors-existing-modified.
- **SQL `control_ids` shim and the Postgres write-privilege probe under
  `default_transaction_read_only`.** Evidence: collectors-existing-modified.
- **Cadence default window per cadence.** The fixed 365-day look-back makes
  annual and longer cadences `insufficient` by construction; v0.13.0 documents
  `--lookback-days`, the code change derives the window from the citation.
  Evidence: core-platform F-3.
- **`save_evidence` permission mode.** New versions are owner-only (0600) on
  POSIX since the hard-link publication change; a store shared between a CLI
  user and an API service account cannot read them. Decide between a
  umask-derived mode and a documented single-owner store. Evidence:
  core-platform F-5.

## MCP

- **Sigstore identity token refresh.** A long-running HTTP or SSE MCP server
  keeps the identity token it started with; once it expires every signed result
  carries `signature=None` and nothing is logged. Re-detect the credential when
  the token leaves its validity window and emit a SIGN_FAILED event. Evidence:
  cli-sweep #5.
- **Signature scope.** The signature covers `structuredContent` (or the
  content blocks when there is none), not the `content` text of a structured
  result; document the limit or sign a digest of the whole result. Evidence:
  cli-sweep #17.

## Alerting and daemon

- **Per-channel alert dedup.** The dedup key is `(slug, state)`, so SMTP
  succeeding while the webhook fails suppresses the webhook for the whole
  window. Evidence: cli-sweep #8.
- **Webhook redirects.** The webhook channel follows 301/302/303 after the
  one-time private-range check and allows an https-to-http downgrade; route it
  through `network_guard.enforce_public_host` with a pinned connection and a
  refusing redirect handler. Evidence: api-cli-mcp-ai F-11, cli-sweep #3.
- **`dedup-list` renames a corrupt file.** The read-only inspection verb goes
  through `_load_state`, which quarantines a corrupt dedup file. Evidence:
  api-sweep #12.

## Stores and records

- **UUID canonicalisation in the governance stores.** `_validate_id_shape`
  accepts braces, `urn:` and uppercase forms and uses the raw text as the file
  name; the POA&M, ai-gov and evidence stores canonicalise. Evidence:
  api-sweep #13.
- **POA&M state machine on create and PUT.** Only PATCH enforces
  `is_valid_transition`; create and PUT accept any milestone status. Evidence:
  api-sweep #16.
- **Read-modify-write locks** on mark-completed (done), ai-gov register,
  POA&M and governance updates. Evidence: api-sweep #14.
- **Proxy trust list.** `EVIDENTIA_TRUST_PROXY_HEADERS=1` trusts every proxy
  (`trusted_hosts="*"`), which voids the per-client rate limit; read a trusted
  proxy list instead. Evidence: api-sweep #15.

## Documentation and audit trail

- **Audit events on the older CLI and REST mutators** (governance, model-risk,

- **Dead `VERIFY_*` events and the health-report event the REST layer never
