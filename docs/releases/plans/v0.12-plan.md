**Build-gate verdict, 2026-08-21.** The gate was "build only if a verified Apache-2.0 source exists." It does not, and the reason is structural rather than a search failure: ISO/IEC 42001:2023 is a **licensed standard**. Evidentia's bundled `iso-42001-2023` catalog is a **Tier-C placeholder stub** — 38 Annex A control *IDs* with the description `[Licensed content — see license_url for authoritative text.]` — because the control text is © ISO/IEC and cannot be redistributed. A crosswalk that names what each 42001 control *requires* in order to map it to an EU AI Act obligation would necessarily paraphrase licensed text; a crosswalk that maps only to bare IDs (`A.6.2.4`) carries no verifiable claim and is not the first-mover artifact the roadmap describes. The existing `nist-ai-rmf-1.0_to_iso-42001-2023` mapping (23 entries, v0.9.3) already sits at that bare-ID ceiling and carries no `verification` field for the same reason. "Clean-room from Annex III + ISO 42001 Clauses 4–10 / Annex A" (the ROADMAP phrasing) presumes a licensed copy on the author's desk, which is exactly what Apache-2.0 redistribution cannot rest on. **Disposition**: v1.1, with the honest framing that the deliverable is an *EU AI Act ↔ 42001 Annex-A-ID* concordance at the same depth as the existing NIST AI RMF one, unless ISO releases Annex A control titles under an open licence. The "zero public OSS equivalent" observation stands, and is now explained: nobody ships one because nobody can ship a substantive one.
