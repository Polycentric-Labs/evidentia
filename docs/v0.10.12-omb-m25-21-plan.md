# v0.10.12 plan — OMB M-25-21 "high-impact AI" migration

> Public, product-only plan. Folds into the in-flight v0.10.12 cycle (CLI↔GUI parity) on branch
> `feature/v0.10.12`. Purely **additive + backward-compatible** — no existing AI-gov inventory
> entry, CLI verb, API route, or UI control changes behaviour. Push/tag are
> release-authority-gated; the full `/pre-release-review` + 3× gate runs before the tag.

## Status (2026-06-23)

Planning. Discovered during unrelated application-prep research: Evidentia's AI-governance module
models **OMB M-24-10**, which was **rescinded and replaced on 2025-04-03** by **M-25-21**
(agency AI *use*) and **M-25-22** (AI *procurement*; replaced M-24-18). Shipping a rescinded memo
as a first-class federal field is a correctness defect for a tool that markets federal-AI
inventory. This plan migrates the model forward without breaking persisted inventories.

## Regulatory facts (verified 2026-06-23, multi-source)

Verified against the WebSearch synthesis, the Wiley alert, and the user-cited sources
(wiley.law, mlstrategies, OPM / Federal Reserve M-25-21 compliance plans). Primary sources:
[M-25-21](https://www.whitehouse.gov/wp-content/uploads/2025/02/M-25-21-Accelerating-Federal-Use-of-AI-through-Innovation-Governance-and-Public-Trust.pdf)
· [M-25-22](https://www.whitehouse.gov/wp-content/uploads/2025/02/M-25-22-Driving-Efficient-Acquisition-of-Artificial-Intelligence-in-Government.pdf).

- **M-25-21** ("Accelerating Federal Use of AI through Innovation, Governance, and Public Trust",
  2025-04-03) **expressly rescinds and replaces M-24-10** (2024-03-28).
- **M-25-22** ("Driving Efficient Acquisition of Artificial Intelligence in Government") rescinds
  and replaces **M-24-18** (procurement). *Out of scope for this change* — Evidentia models no
  M-24-18 surface today; noted for completeness + a v0.11 ROADMAP seed.
- M-25-21 **collapses the old "rights-impacting" / "safety-impacting" split into a single
  "high-impact AI" category**: AI whose output is a *principal basis* for decisions/actions with a
  significant effect on (1) civil rights / civil liberties / privacy; (2) access to essential
  services (education, housing, insurance, credit, employment, …); (3) critical government
  resources / services; (4) human health & safety; (5) critical infrastructure / public safety;
  (6) strategic assets / resources.
- **Seven minimum risk-management practices** for high-impact AI: pre-deployment testing; AI
  impact assessment; ongoing monitoring + adverse-impact detection; human training/competency;
  enhanced human oversight & intervention; consistent remedies & appeals; end-user/public
  feedback. **Structured tracking of these 7 is deferred to v0.11** (see ROADMAP seed below).
- Governance roles (CAIO within 60d; AI Governance Board within 90d) are agency-org facts, not
  per-system inventory metadata — **not modelled** here.

## Decisions (locked)

1. **Scope = consolidated determination + basis** (not the full 7-practice checklist). A new
   `omb_m_25_21` core module with a determination enum + a basis enum, surfaced as one new
   Optional registry field via a small sub-model. The 7 minimum practices are documented in
   docstrings/guide only this cycle.
2. **Additive + backward-compatible, no breaking deprecation.** The legacy `omb_m_24_10` module +
   `OMBImpactCategory` + the `omb_impact` registry field + `set-omb-impact` CLI/API verbs all keep
   working and serializing. **No runtime `DeprecationWarning`** (would trip strict CI / operator
   warnings-as-errors) — deprecation is documented in docstrings + docs only.
3. **The two fields stay independent.** We do **not** silently auto-derive the new determination
   from a persisted legacy value (that would fabricate a federal determination). The old→new
   mapping is an **explicit, operator-invoked crosswalk helper**.
4. **Folds into v0.10.12** (the CLI↔GUI parity cycle). The new `set-high-impact` verb ships as a
   matched CLI ↔ API ↔ UI triple, on-theme for the cycle.
5. **Full 7-practice tracking → v0.11** (federal-compliance theme). ROADMAP seed added this cycle.
6. **History is immutable.** Ship-record docs (`security-review-v0.9.5/6.md`, old `v*-plan.md`)
   keep their M-24-10 references — they record what shipped then.

## Components

### A — Core models (`packages/evidentia-core/src/evidentia_core/ai_governance/`)

1. **NEW `omb_m_25_21.py`**:
   - `HighImpactDetermination(str, Enum)`: `HIGH_IMPACT="high_impact"`,
     `NOT_HIGH_IMPACT="not_high_impact"`, `NOT_ASSESSED="not_assessed"`. Stable string values
     (persisted in YAML/JSON inventories — same stability contract the legacy enum carries).
   - `HighImpactBasis(str, Enum)`: the six M-25-21 consequence categories —
     `civil_rights_liberties_privacy`, `essential_services_access`, `critical_government_resources`,
     `health_and_safety`, `critical_infrastructure`, `strategic_assets`. Docstrings cite the memo.
   - `OMBHighImpactAssessment(EvidentiaModel)`: `determination: HighImpactDetermination`,
     `bases: list[HighImpactBasis] = []`, `rationale: str | None = None`. Mirrors the
     `FIPS199Categorization` sub-model pattern; the natural extension point for the v0.11
     7-practice checklist. (Validator: non-empty `bases` only meaningful when
     `determination == HIGH_IMPACT` — advisory, not enforced, to avoid rejecting operator drafts.)
   - `triggers_minimum_practices(determination) -> bool` (True iff `HIGH_IMPACT`).
   - `crosswalk_from_legacy(OMBImpactCategory) -> OMBHighImpactAssessment`: rights/safety/both →
     `HIGH_IMPACT` (coarse basis mapping, flagged in `rationale` as legacy-derived → operator
     should review against M-25-21); `neither` → `NOT_HIGH_IMPACT`.
   - `__all__` exports all of the above.
2. **`omb_m_24_10.py` (kept, frozen):** module + `OMBImpactCategory` get a deprecation note in the
   docstrings pointing at `omb_m_25_21` and the rescission fact. **No behaviour change, no warning.**
3. **`__init__.py`:** export the new symbols additively (legacy exports retained).
4. **`registry.py`:** add `omb_high_impact: OMBHighImpactAssessment | None = None` (Optional →
   backward-compat). Keep `omb_impact` (deprecated docstring). Update the module docstring's
   federal-field list.
5. **`scr.py`:** add `_high_impact_escalated(prior, new)` (→`HIGH_IMPACT` is transformative); wire
   into `classify_change` alongside the retained legacy `_omb_impact_escalated`. Extend
   `_auto_summary` (report the new field's diff) + `_default_customer_impact` (consider the new
   determination) **additively** — legacy behaviour unchanged when only the legacy field is set.

## Backward-compatibility invariants (the bar)

1. A v0.9.6–v0.10.12 inventory entry with `omb_impact` set and no `omb_high_impact` loads and
   serializes unchanged.
2. `OMBImpactCategory` and `triggers_minimum_practices(OMBImpactCategory)` keep their import paths
   and string values.
3. `set-omb-impact` (CLI + REST) and `AI_SYSTEM_OMB_CLASSIFIED` keep working and firing.
4. No new required field anywhere; every new field/param is Optional/defaulted.
